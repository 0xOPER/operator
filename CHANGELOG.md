# Changelog

All notable changes to OPERATOR are documented in this file.

## Unreleased (`main`)

### Added
- Signed environments (`docs/charter.md`, M1 first slice). A program's `charter.toml` declares `[[environment.<name>]]` blocks: a digest-pinned image that must be present locally and is never pulled, the runtime, devices, host mounts, no network, a read-only rootfs, size-capped scratch, a non-root user, and memory, CPU, process and wall limits. `bin/environment.py` is the only container client: `operator environment validate <dir>` checks the charter and `operator environment run <dir> --env NAME -- <cmd...>` is the door. The arm ruling is verified before every run, so an edited environment is an unsigned program, and every run files a hash-chained receipt (`env:<name>`). A contract row with `env = "<name>"` runs its check there with the jail's read-only overlays mounted at their paths, and its receipt names the environment and the image. The block sits inside the signed closure like every other program file. A seat with `env = ["<name>"]` gets the same door inside its jail as a socket (`/op-envd.sock`, the client `bin/lib/op-env.py`): the engine serves it, one request at a time, grants and `env_minutes` checked on its side, and the turn's end ends it.
- A fingerprint of the work directory in every environment receipt (M1). `work` is 16 hex of every regular file's path and bytes under a run's work directory, within a budget of 20,000 files and 1 GiB; a link is named and never read, and past the budget the receipt says `workcap=1`. A contract row's check carries the same fingerprint of what it left in `/w/out`. Neuter rows for the key, the bytes, the link law, the budget and the capped receipt.
- Neuter rows for every environment guard (59) and `HK-battery-path` for the push gate.
- A seat's network from the charter (M2, first slice; `docs/charter.md`). `bin/reach.py` turns a seat's `network` grant and the charter's `[reach]` into the egress policy its jail runs: the profile names categories, `allow` widens, `deny` beats every allow, `pins` vouch an address. A grant outside the charter refuses at `team validate` and again where the jail is built. In the adapter jail the egress proxy is the only door (its socket bound in, a relay on 3129, the standard proxy variables with the broker excluded), with one log row per connection. `network` joins the `tested_classes` of `claude-code`, `codex` and `opencode`; the new `net-allowed` conformance cell fetches the charter's host through the proxy, sees a host outside it refused and logged, and a credential shape riding a proxy-visible header refused the same way. `egress-proxy.py` refuses a credential shape in a request head before resolving or connecting, naming the host and never the bytes; inside an HTTPS tunnel it reads nothing, as the docs say. 21 neuter rows.
- `bin/derive.py` (M3, first slice): a sealed baseline found in a repository rather than written. `derive rows <work-repo>` reads the tree at a commit and writes contract rows for pytest, unittest, Makefile targets, package.json scripts, cargo and go, each sealed by an oracle that pins what the runner reads. `derive pin` runs every derived row once at the commit through the check jail and reports the red ones as the known-red baseline, filing nothing. 7 neuter rows.
- The `shell` class (M2). A seat's `shell` grant rides its attempt, and `shell` joins the `tested_classes` of `claude-code`, `codex` and `opencode` with a `shell-allowed` conformance cell: a command runs in the jail and an out-of-tree write is refused by the read-only bind. On every shipped adapter the jail is the law: none keeps a per-command law, so the grant is not compiled to the CLI's permission rules (measured at the pin: `claude-code` runs a write into an existing directory with no rule and asks before it creates one; the cell's command is the write, into a directory the fixture provides). 2 neuter rows.
- The `declared` rule and `net.allow` (M2). `operator reach allow <dir> --seat <seat> --host <host>` opens one host on 443 for a seat that already holds a network grant, for `declared_ttl` seconds while fewer than `declared_max` are live, never a denied host. The live declarations sit under `<program>/runs/`, each one a row in the call log, and they ride the seat's next turn as `host until <UTC>` policy lines. The operator seat's directive `{"verb": "net.allow", "seat": ..., "host": ...}` is the same law. Neuter rows for every bound.
- The operator seat's brief names the hosts the charter's proxy refused in the run's attempts, per seat with a count and fenced as untrusted, so `net.allow` answers on evidence. 3 neuter rows.
- `test/planted-hook-walk.sh`: the delivery invariant as a standing walk. Hooks and config-driven commands are planted in an attempt's `.git` after a real worker turn, the real chain (seal, gate, collect, candidate) runs, and nothing may fire on the host; a control proves the plants are live, and `--sabotage` runs the walk against an engine copy whose collector runs git in the attempt on the host to show that it can fail. CI runs both.
- The `read` class (M2). A seat's `read` grant reaches host directories, bound read-only at their own path in its jail. The charter lists them (`[reach].read`), the grant names one of them or a directory inside it, and every path meets the environment's mount law and a stricter one (`bin/environment.py` `read_refusal`: no link anywhere on the path; never a system path, a container socket, the engine's own tree, its state, the program or anything at or above them; never a credential directory; never a home). The law and the charter are held again where every worker jail is built, and beside a network grant that door asks the newest arm ruling for the signed `rule-of-two` waiver (a worker that can read a host directory and talk to the network can exfiltrate it); until now the waiver was only named at validate. `read` joins the `tested_classes` of `claude-code`, `codex` and `opencode` with a `read-allowed` conformance cell. 20 neuter rows.
- The writable clone for `shell` seats (M2). A seat that holds `shell` gets a real clone in its jail: the repository binds read-write, `.git` with it, so the worker branches in it and adds worktrees of its own. Until now `.git` was a read-only bind of its own, which ruled out worktree fan-out. This changes what an existing `shell` grant gives: the key is declarative and gates shell-class features. The class is earned per adapter: the seat's `shell` grant must be backed by the adapter's manifest (`tested_classes`, behind the `shell-allowed` and the new `clone-allowed` conformance cells), and both are held again where the jail is built. A seat that does not ask, or asks on an adapter that has not earned the class, keeps the read-only `.git`, and a review turn's repository stays read-only whole. Nothing a worker plants in the clone reaches the host, by structure (`docs/charter.md` section 5): no engine git runs in the attempt after the build, and the seal stages the work tree into a git directory of its own, which never delivers `.git`. There is no kill switch to set, because a setting written into a config the worker can rewrite would stop nothing where the worker already runs everything. `test/planted-hook-walk.sh` gains the clone leg (the plants written by the worker's own turn from inside the jail), with its sabotage. 6 neuter rows.

### Changed
- A seat that holds `ro` beside `network` now needs the signed `rule-of-two` waiver, as a seat that holds `read` beside `network` does. This is a behaviour change for programs that hold both today. Until now the seat key `ro` bound a host path read-only beside a network grant with no charter and no waiver at all, and `team validate` did not name one: the exfiltration path the rule of two exists for (measured: one turn read a host directory with the proxy in the same jail). Where every jail is built the seat's jail is now refused until the newest arm ruling carries the waiver (`operator ruling sign <dir> --kind arm --waive rule-of-two`), or one of the two grants is dropped, and `team validate` names the waiver for `ro` as it does for `read`. `ro` is not folded into `read`: it still binds on the team's signature alone, and what it binds on its own is unchanged. 3 neuter rows.

### Fixes
- The push gate no longer hands its repository to what it runs. Git passes a hook its repository as `GIT_DIR`; inside a linked worktree that is an absolute path, and `scripts/release-lint.py --selftest` builds a scratch repository with `git init`, which re-initialised the pushed repository instead: the scratch commits landed on the branch being pushed and the repository was turned bare. It worked from a main clone only because `GIT_DIR=.git` is relative there. The gate now unsets the discovery variables after it changes to the tree, the lint's own git calls take an environment without them, the lint selftest proves its scratch repository is its own under a caller's `GIT_DIR`, and the hooks selftest pushes from a linked worktree. Rows `HK-prepush-gitdir` and `RL-scratch-hermetic`.
- `bin/review.py`: both selftest suites now report a failure (exit 1) when an arm crashes with VOID after an earlier arm already recorded a failure. A break that lets a forged verdict deliver moves the fixture out from under the arms after it; the suite used to exit 2 and forget the failure it had printed, which is why the ratchet reported four review rows as VOID. The truncated-pack arm also records a pack that got past the guard, whatever the unguarded path dies of afterwards.
- `test/neuter.py`: a row that does not die prints the last lines of the mutated test's output, so a VOID or a survivor can be told apart from an environment that broke the test.
- `.githooks/pre-push`: the cleanroom battery runs by its repo-relative path. The gate handed the room an absolute host path, which cannot exist inside it (the tree is `/work/operator` there), so every push from a Linux clone with the hooks installed was refused. `scripts/setup-hooks.sh --first-level` proves the step really runs (a failing battery refuses the push) and the neuter row `HK-battery-path` pins it.
- `bin/environment.py`: the worker's environment door wakes its serving thread when the turn ends. Closing a listening socket from another thread does not wake a thread blocked in `accept()`, so every turn that held a door waited out the join's whole 45 seconds and left the thread behind. The end of a turn now connects to its own socket once; a selftest arm times the close.
- `bin/spawn.py`: `adapter_prepare` runs no git inside an attempt. It asked the attempt's own repository, on the host, whether the adapter's config file is tracked (`git ls-files`), so an attempt driven again after a worker's turn ran whatever that repository's config named: a planted `core.fsmonitor` fired on the host (measured). The answer now comes from the build (`tracked.json`, what the start commit tracks without the names the attempt hides), written before any worker exists; a listing that will not read is VOID, where a failing git call used to read as "not tracked". `test/planted-hook-walk.sh` gains the leg that measures it (the engine's own verb on a turned attempt), with a sabotage per leg, and its control now covers the plant that leg could fire. A static half in the selftest (`GIT_FUNCTIONS`, `GIT_PARENT_FUNCTIONS`) refuses a git call anywhere else in the module, and after the build anywhere but the run's parent. 4 neuter rows.

### CI
- `Dockerfile`: the base image is pinned by digest (`ubuntu:24.04@sha256:562111b8...`), so the image CI builds is the one that was reviewed and not whatever the tag serves that day.
- `.github/workflows/ci.yml`, `.github/workflows/proofs.yml`: the CLIs the conformance and proof cells run are installed from a committed lockfile (`test/cli-pins/package-lock.json`: every tarball by its sha512, checked against the registry's own bytes) with `npm ci --ignore-scripts`, as the runner's user and not as root. The workflows used to name versions and trust whatever the registry served that day, as root, running whatever the packages called a postinstall. What those postinstalls do (stand the linux-x64 binary at the wrapper's bin) is done by link instead. `scripts/verify-ci-pins.py` refuses a tree where an npm command installs any other way, a lockfile entry has no hash or no registry URL, a dependency is not at an exact version, or a `FROM` has no digest.

## `v0.1.0` — 2026-11-26

Initial public release of OPERATOR under the Apache License 2.0.

- Linux `bubblewrap` confinement (`bin/lib/jail.py`, `bin/spawn.py`), host-side API credential brokering (`bin/broker.py`), and allowlisted egress proxy (`bin/egress-proxy.py`).
- Tamper-sealed contract verification (`bin/contract.py`) with pinned read-only test overlays, root runner-config restoration, `expect_base_fail` differential checks, twin `control` rows, and `pytest-guard` receipts.
- Signed SSH closure rulings (`bin/ruling.py`), cross-family review gate (`bin/review.py`), bounded unattended operator loop (`[seat.op]` in `bin/run.py`), and read-only loopback panel (`bin/panel.py`).
- Commercial CLI adapters for `claude-code`, `codex`, `opencode`, `zcode` (experimental), and offline `stub`.
- Cleanroom selftest battery, 461-row guard-mutation sensitivity ratchet, hollow-suite sabotage suite, CI CLI conformance cells, CodeQL, OpenSSF Scorecard, and offline Sigstore Rekor verification for `CLAIMS.md`.
